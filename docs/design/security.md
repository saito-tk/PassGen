# 安全性と構成

## 境界

- Kotlin Multiplatformで生成・入力検証・記号反映・エントロピー計算を共有する。
- AndroidはJetpack Compose / Material 3、iOSはSwiftUI。ComposeによるiOS画面の共有は行わない。
- オフラインの生成専用アプリ。アカウント、履歴、同期、広告、解析SDK、サーバーを持たない。
- パスワード・画像・OCRテキストをディスク、設定、ログ、バックアップへ保存しない。
- 生成条件・表示状態・保護設定と、名前付きの生成プリセットをUserDefaults / アプリ専用SharedPreferencesに保存し、サイズ・バージョン・許可集合を検証して復元する。プリセットは生成条件だけを別の版付きデータに保存し、秘密・コピー印・表示・安全性設定を含めない。破損や未知バージョンのプリセットを自動で上書きしない。
- 生成した秘密とコピー済みの行IDはメモリ中だけに保持する。背景移行では処理中の生成を止め、生成済みの値と印は維持する。手動消去・再生成・プロセス終了で破棄し、再起動時には復元しない。
- JVM / Swiftの文字列とOSクリップボードは完全なメモリ消去を保証できない。root化・脱獄・侵害されたOS、外部カメラによる撮影は防御範囲外。

## 生成

- Android: java.security.SecureRandom。iOS: Security.SecRandomCopyBytes。乱数取得失敗時は生成失敗として停止する。
- 独自PRNG、時刻シード、Kotlin Random、LLM生成パスワードは使用しない。
- 範囲化は16bit乱数のrejection sampling。剰余だけで範囲化しない。
- パスワードとEFF 7,776語のパスフレーズを選択可能にする。数字のみはパスワード側の文字種設定。形式は用途の違いであり、安全性の順位ではない。
- 必須文字種の条件は候補全体のrejection samplingで満たす。文字種ごとの先取り＋シャッフルによる偏りを避ける。
- 大文字・小文字・数字・記号は1文字ずつ許可集合を指定できる。重複を除去し、文字種外の文字は拒否する。ONでも選択・除外の反映後に有効文字0となる文字種は、OFFと同様に生成対象から外す。「各文字種を必ず含める」とエントロピーも、有効文字が残る文字種のみを対象とする。全体で有効文字0の設定は引き続き拒否する。
- 似た文字の除外対象も `O o 0 I l 1` から個別選択できる。除外中の文字はUI上で明示し、許可集合との積で実効集合を決定する。
- 同一文字連続禁止は直前文字を除いた集合から一様選択する。必須文字種と併用しても全候補の棄却で一様性を維持する。
- 試行回数を制限し、条件が厳しくても安全性を落とす代替方式へ切り替えない。キャンセルを定期確認する。
- エントロピーは生成空間から計算する。固定区切り文字にエントロピーを加算しない。実際のサービスの安全性・解読時間を保証しない。
- 文字列長4〜999,999、件数1〜min(1,000, floor(9,999,990 / 長さ))。巨大な結果はプレビューを100文字に限定する。

## OS保護

- AndroidはINTERNET権限なし、backup無効、オーバーレイ対策、機密クリップボード印を使う。FLAG_SECUREは初期状態で有効。撮影・収録防止を設定で変更できる。
- iOSは非アクティブ時の画面を初期状態で覆う。覆い全体は「アプリ切替時に画面を隠す」で選択でき、主画面・各シートに反映する。画面収録の保護とは独立した設定として保持し、既存データにこの項目がない場合はオンを引き継ぐ。オフ時はアプリ切替画面などに内容が映り得ることを案内する。UIKitのsceneCaptureStateを開始・停止・再アクティブ化時に読み、収録中の保護が有効な場合は秘密と画像の表示・コピーを制限する。停止時に解除し、ユーザーの表示設定自体は変更しない。iOSの静止画スクリーンショットを完全に禁止できるとは表現しない。
- コピーは明示操作のみ。初期値は端末内限定（iOS localOnly）・30秒。背景移行ではコピーを消去しない。期限5〜600秒、自動消去の有効/無効、iOSのUniversal Clipboard許可を選べる。設定変更は次のコピーから適用する。iOSはOS expiration、Androidは所有識別付きタイマーを使い、OSが先に消去し得ることを示す。Androidには共通のlocalOnly APIがないため端末側の共有設定を案内する。
- Androidで背景の所有確認がOSに拒否された場合は、所有トークンと単調時計の期限だけを保持し、window focusの復帰時に再確認する。別の内容であれば消去しない。プロセス終了や背景制限下での厳密な期限消去は保証しない。参照: [Androidのクリップボード制限](https://developer.android.com/about/versions/10/privacy/changes#clipboard-data)。
- クリップボードの他アプリによる置換は削除しない。アクセシビリティは秘密を読み上げず、明示した表示操作だけで視覚表示する。

## スクリーンショットの記号取り込み

- iOS標準PhotosPickerで利用者が選択した画像だけを処理する。写真ライブラリ全体への権限を要求しない。
- Visionで許可文と記号行、文字種表の記号セル、または文字の大半が記号の一覧を候補領域として特定。文字種表では大文字・小文字・数字の行と列の整列、および直前のパスワード定義を確認する。候補領域の一次OCRと再OCRを統合し、全角ASCII相当のみ半角化する。記号行だけを英語OCRで再読取し、連結した字形は元の字形を保った間隔追加でも認識する。iOS 27以降の対応端末でSystemLanguageModelを明示し、記号行の元画像と間隔・拡大の異なる画像を直接入力する。プロンプトへ対応する半角32記号を出力語彙として渡し、画像の許可リストとは区別する。日本語の誤認文字から括弧を機械的に推測しない。
- クラウドモデル・ネットワーク・ツール呼び出しへフォールバックしない。
- 解析結果・元画像のプレビュー・候補の手修正は、編集画面を閉じるまでメモリ内に保持する。背景移行では覆いの設定に従い、処理中の読み取りは中断し、前景復帰で再開する。閉じる・中止・適用・画像変更では古いタスクを無効化し、遅れて返る結果を反映しない。生成パスワードも背景ではメモリ内に保持し、処理中の生成のみ中止する。
- モデルは不確実な提案器。画像出力は対応ASCII32記号へ制限する。長い密な行はenum配列からアプリでASCIIへ変換し、短い一覧は従来の文字列出力を検証する。許可文がない記号の並びも候補化するが、サービスが使用可能と定めた記号だとは断定せず、利用先の条件を確認するよう表示する。OCRと画像モデルを併用しても誤認・欠落は残るため、元画像を確認画面に出し、全32記号から修正して明示適用する。標準ASCII並びからの穴埋めは禁止する。独立した複数の領域は自動で合成しない。記号一覧の近くの禁止・入力例の表現、URL、文章、同じ文字だけの伏せ字・罫線を除外する。近接した記号断片は位置関係でまとめ、間に文章がある場合は分離する。汎用一覧の探索は観測512件・記号断片96件までに制限する。
- 読み取り内容は信頼しないデータとして扱う。ユーザーが根拠と記号を確認し、適用するまで生成条件を変更しない。
- 利用不可・失敗時は理由を示し、手入力と記号パレットを使えるようにする。

## 依存関係

Google / JetBrains / Appleの保守されている標準・公式ライブラリに限定する。
最新安定版を基本とし、Kotlinの公開互換範囲内でAGP / Gradleを固定する。
依存チェックサム、Gradle配布物チェックサム、バージョン固定で取得の再現性を確保する。
「最高峰」や「絶対安全」は検証可能な保証にならないため、脅威モデル・テスト・制約を明示する。

### 教材の具体値（タスク20）

- 平文・使い回しの例は公開の架空値のみで、生成エンジンの入力やユーザーの資格情報を使わない。アプリ内ではハッシュ計算を行わず、固定の共通教材データを表示する。
- ハッシュ例はArgon2idのPHC保存形式全文（バージョン・計算設定・16バイトのソルト・32バイトの計算結果を含む）を表示する。架空の同じ入力、同じメモリ/反復/並列設定で、共通ソルト・個別ソルトの違いを比較する。Argon2はソルトが必要なので、無ソルトのArgon2形式を創作しない。
- Node.js標準のArgon2idでオフライン計算し、RFC 9106のベクトルと3つの例を開発用スクリプトで検証する。モバイルアプリの依存ライブラリは追加しない。設定例はOWASPの最小構成（m=19456 KiB, t=2, p=1）に合わせる。例示の値を利用者のパスワードとして推奨しない。
- 参考: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[RFC 9106 §5.3](https://www.rfc-editor.org/rfc/rfc9106.html#section-5.3)、[Node.js Argon2](https://nodejs.org/api/crypto.html#cryptoargon2syncalgorithm-parameters)。


## 説明用の公開例

`SecurityGuideExamples`は利用者の入力、生成器、クリップボードに接続しない読み取り用の教材。公開の24文字見本・7単語の形を安全な認証情報と評価しない。弱い例は攻撃で試されるパターンを示すためであり、例にない値の安全性を判定しない。数字の比較は0〜9を各位置で独立・一様に選ぶ条件（先頭0を含む）を固定する。候補数を解読時間に換算せず、生成ルールや利用先の攻撃制限による差も混同しない。固定の区切りに追加エントロピーは与えない。

### 記号案内の書式解析（タスク25）

許可・見出しの位置と、記号値の引用・区切り・名前付き表記を共通Kotlinで解析する。全角ASCII相当の正規化でも、Swiftへ渡す範囲は元のUTF-16座標を維持する。書式の引用符や区切りを候補に混ぜず、画像モデルによる実際の字形の補正を許す。OCR集合を正解集合として固定しない。名前だけから記号を作らず、印字と一致した名前付き項目はその字形だけに限定する。

画像モデルの有効な候補は行ごとに反映し、その行の異なる画像の候補を合わせる。一次OCRと再OCR、または複数の再OCRが一致した記号は、書式制約の範囲内で維持する。空・極端に少ないモデル候補では行のOCRを維持する。どちらも不確実な提案のため、照合・手修正・明示適用は必須。除外条件・明示された正規表現やコード範囲・入力例・対応外字形を許可記号へ推測変換しない。限定許可の「次の記号以外は使用できません」は狭い定型構文だけ対応し、他の否定条件が併記された場合は使用しない。引用と直接列挙が混在した一覧や、列挙の直後の除外条件を無視して、一部分だけを取り込まない。


### 括弧と折り返し許可語（タスク26）

許可語の途中で改行した注釈は、位置の近い同じ列の記号断片・既知の述語断片だけ結び、元のUTF-16範囲を物理行の画素へ戻す。別の入力項目や伏せ字を飛び越えない。閉じる括弧は許可述語で確かめ、値としての括弧を構文の入れ子にしない。注釈内の誤認は文字列の補完に使わず、記号が過半を占める短い画素領域の選択に限定する。

長い密な行はモデルに32記号のenumを選ばせ、アプリでASCIIへ対応付ける。短い一覧は従来の文字列出力とASCII検証を維持する。密な長い行は重なる画素領域でも読み、元画像の字形を変形しない。長い列でOCRにないモデル追加候補は、複数の画像読取の一致、または混同した接続字形3種類のOSフォント輪郭との一致を必要とする。輪郭の別の部品だけで文字を追加しない。輪郭処理は画像200万画素・前景12万画素・構成部192個を上限とし、越えた場合は判別不能として扱う。バックスラッシュは方向を画像で追加確認する。小さいOCR集合からほぼ全語彙を提案した場合は採用しない。縦棒・スラッシュ・キャレット等の部分を別の文字として推測で追加しない。追加確認もモデルの提案であり、元画素との照合・明示適用を省略する根拠にはしない。ログへ画像・OCR・モデルの読み取り文字列を出さない。

### AIによる案内領域の補完（タスク27）

既存の画像AI＋OCR経路が候補を得た場合は維持する。OCRが明確な禁止・範囲・複数規則等の手動確認を示す場合もAIで覆さない。案内を見つけられなかった場合だけ、対応環境の端末内画像モデルが案内領域を補完する。

補完経路は文字列を認識しないVisionの位置検出から最大8つの領域を作る。位置が得られなければ固定3領域を確認する。AIが選んだ元画素を読み、通常はOCRで値部分の位置・引用・区切りも補助する。OCRテキストがなくても画像読取経路は動作する。明確な書式制約をAIだけで無視しない。

モデルの空回答・拒否・分類不能では既存の確認案内を維持する。拒否された領域の安全フィルターを外さない。範囲・正規表現・禁止一覧・競合する規則をAIに展開・反転させない。領域判別前の画像には入力欄などが含まれ得るが、処理は端末内のみ。外部ツール・ネットワーク・画像やモデル応答のログ保存を追加しない。

AI単独での正確な転記は保証しない。比較で欠落を確認したため既存の併用経路を維持する。どちらも提案に留め、画像との照合・手修正・明示適用を必須とする。


### プリセットのQR転送（タスク37）

転送対象は名前と17項目の生成条件だけに限定し、秘密・乱数seed・コピー状態・画面保護の設定を含めない。共有する画像はQRだけを描画し、アプリのウィンドウや生成結果を撮影しない。Androidの共有URIは専用キャッシュ1ファイル用の非公開FileProviderから読み取り権限だけを付ける。

旧形式の語彙・順序・範囲を形式別readerへ固定し、現行UIの初期値へ暗黙に置き換えない。CRCは破損検出であり送信者認証ではない。読み取った値は上限・予約bit・整数の最短表現・文字列を検証し、未知形式や複数QRは拒否する。OS内で画像を解析し、URLアクセスやモデルへの送信を追加しない。内容確認と新規登録を必要とし、同名の上書き・現在の設定への自動適用を行わない。詳細と互換性テストは [QR形式](preset-qr.md) を参照。


### 適応レイアウトとメモリ内の結果（タスク38）

左右カラムと結果シートは同じ生成モデルを参照し、生成値を画面の保存状態へ複製しない。AndroidはViewModelで結果を保持し、Saveableには表示要求・編集タブ・展開状態・スクロール座標のみを保存する。iOSも親Viewのモデル・コピー状態を維持したまま表示先を変える。キャプチャ保護、背景時の生成停止と完了済み結果の保持、コピーの有効期限・所有確認は既存の挙動を保つ。

Androidの結果行は、コピー済み状態をComposition内で読み取ってからアクセシビリティの説明へ渡す。画面外に事前構成された行のSemanticsコールバックから直接Observable状態を読み、コピー印の更新時に未接続ノードを通知対象へ含めない。読み上げ用の値へパスワードを渡さず、全文コピーと表示上限は従来どおり分離する。


## Androidの編集中データ（2026-10-31）

画面再作成による入力消失を防ぐため、未保存のプリセット名・編集対象・QR登録前の設定・記号貼り付け文はViewModel配下のEditorSessionにだけ保持する。生の貼り付け文は秘密を含み得るため、rememberSaveable・SavedStateHandle・設定JSON・QR出力には追加しない。明示的にシートを閉じる時とViewModel終了時に参照を破棄し、新しいモデルでは復元しない。生成結果・コピー印の保存仕様や画面保護の初期値は変更していない。

### プリセットQRのカメラ読取

カメラ利用時だけ権限を要求し、QR metadata / 輝度だけを端末内で解析する。録画・撮影・ファイル保存・外部送信・マイク取得は行わない。背景と画面終了で解放し、遅延した検出・重複通知を破棄する。アプリ形式の整合性検証に通った候補だけを確認画面へ渡し、URLの起動や自動登録/適用はしない。CRCは破損検出であり共有元の認証ではないため、従来の共有元確認と明示登録を維持する。画像選択には写真全体の権限を要求せず、カメラ拒否時も利用できる。
