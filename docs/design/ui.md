# UI / UX

## 画面密度

ユーザーのフィードバックに基づき、大きな宣伝見出し・英語タグライン・装飾用リング・未生成カードを削除。
メイン画面は生成形式、文字数 / 件数、文字セット、生成ルールに集中する。
説明は操作に必要な範囲に絞り、安全性の詳細は専用シートに置く。
密度を上げても文字の個別選択はiOSで44pt、Androidで44dpの視覚面＋周辺間隔を確保する。

## 生成形式

- パスワード: 大文字・小文字・数字・記号を個別指定する。
- パスフレーズ: EFF 7,776語から6〜12語を無作為に選択する。
- 数字だけの生成は、大 / 小文字・記号を利用者が個別に無効にして設定する。誤操作を避けるため一括切替ボタンは置かず、似た文字の除外も利用者の選択を維持する。
- パスフレーズの区切りは半角スペース（初期値）、`-`、`_`、`.`。固定の区切り文字にはエントロピーを加算しない。

## 文字セット

文字種ごとのタブでA〜Z、a〜z、0〜9、ASCIIの32記号を1文字ずつ切り替える。
文字セットの直下に「現在選択中の文字」を置く。大文字・小文字・数字・ASCII32記号をすべて並べ、実際の生成対象を濃色、未選択・文字種無効・似た文字として除外中の文字を淡色で示す。参照専用の一覧とし、選択操作は文字セット側へ集約する。狭い画面では各行を折り返す。文字種全体の有効 / 無効と、各文字の選択状態は独立して保持する。生成ルールは全幅の開閉行にし、ネイティブスイッチをインデントしない。
全選択 / 解除（iOSでは反転も可）を提供する。
似た文字として除外中の文字はグレー表示し、理由を表示する。除外対象自体も生成ルールから個別変更できる。

## 結果シート

iPhone縦画面では88ptの最小detentを持つネイティブシートを常設する。最小状態だけ背景の設定を操作でき、表示切替と結果本体は隠す。生成・再生成・停止は右上へ集約し、「閉じる」は置かない。下へドラッグすると最小状態へ戻る。1〜3件は中間、それ以上や拡大文字では大きく開き、多数の結果はスクロール・拡大して閲覧する。
iPad・横画面とAndroidはモーダル構成を維持し、メインの生成ボタンを小型化して結果シート表示中は隠す。記号・設定画面は結果シートと同時に競合させず、閉じたらiPhone縦画面の最小シートへ戻す。
各項目には番号、マスクされた結果、個別コピーを置く。実文字数は一覧上部に一度だけ表示し、100文字を超える結果がある場合は「先頭100文字のみ表示」も同じ場所にまとめる。現在の設定ではなく生成済みの結果から算出し、パスフレーズなど長さが異なる場合は最短〜最長の範囲で示す。強度の数値も共通条件としてまとめる。iOSはMac版と同じ文字単位の折り返しと無制限行UILabelを使用する。Androidは表示用文字列の各文字間にゼロ幅の改行候補を入れ、行数による省略を外す。64文字は全文を表示し、100文字を超える生成値は先頭100文字をプレビューする。表示用の改行候補は生成値・コピー値に含めない。読み上げには秘密を渡さない。
目のアイコンは実際の表示状態（表示中はeye、非表示はeye.slash）を示し、読み上げのラベルは次の操作を伝える。再生成後も表示設定を維持する。
消去を押したらiPhone縦画面では最小シートへ戻し、モーダル構成では閉じる。背景移行時は処理中の生成だけ停止し、完了した結果・コピー済みの印・シートの表示状態を保持する。コピー済みの内容は背景で消さず、設定した期限に従う。

## OSごとの構成

AndroidはMaterial 3の入力欄・分割ボタン・選択パレットを使用。幅が広い場合は条件と文字セットを分け、縦 / 横のヒンジを避ける。
分離する縦ヒンジでは生成ボタンと結果シートを右側へ配置する。
iOSはSwiftUIのネイティブ分割選択、トグル、開閉行、Listシートを使用。iPadでは条件と文字セットを2ペインで扱う。
Liquid GlassはiOS 26以降の標準ツールバー・シート・主要アクションに使用し、透明度抑制時は不透明な操作面にする。
文字サイズ拡大では折り返し・スクロールを許可し、iPadでもアクセシビリティ文字サイズは1列を優先する。

## 保持とコピー

生成条件・表示状態・保護設定だけを端末内へ保存する。生成結果・読み取り内容・コピー済み状態は保存しない。
マスクは区切りなしの固定長。表示を選んだ場合は再生成でも維持する。コピーは各行のアイコンに✓を添え、複数行のコピー済み状態を保持する。
設定と安全性はメイン画面から常に開ける。iOSでは収録中も設定操作を許可し、保護対象の結果と画像だけを隠す。停止後は表示・コピーを再開できる。
安全な使い方は設定とは別の読み物ページへ置き、公式のヘルプへリンクする。

## 読んで試すセキュリティガイド

「なぜ使い回しは危険？」から、サーバーのDB（データベース）に保存される情報として、平文とハッシュ化を比較する。架空のパスワードを入力・平文保存の両方に表示し、同じ文字列が残ることを示す。使い回しの図は同じ値 / 別々の値を切り替えると、A・B・Cに表示する具体的なパスワード例と影響先の表示が変わる。詳しい説明と出典は開閉式にし、図と短い説明から読める構成にする。図では実際のパスワードを扱わない。

「2要素と2段階、何が違う？」では確認の手順と要素の種類を別々に表示する。タブは「2段階」「2要素」「パスキー」とし、質問・認証アプリ・本人確認必須のパスキーを本文の具体例として切り替え、同じ種類を重ねる場合と異なる種類を組み合わせる場合を比較。知識・所持・生体、MFA、SMS / 一時コード / FIDOの違いと復旧の注意点は開閉式で読む。呼称だけで安全性を判断させず、パスキーの本人確認条件を明記する。小型画面と文字サイズ拡大では図を折り返す。

ハッシュ化の補足には、同じパスワードを使う2人の保存値を並べ、共通ソルト / 利用者ごとの個別ソルトで切り替える図を置く。同じ方式・設定で保存値の一致が手掛かりになる条件を明示し、全員で同じソルトを使う問題も説明する。個別ソルトによる一致比較の防止と、候補を計算する推測攻撃が残ることを区別する。保存値は架空のパスワードから事前計算した完全なArgon2id形式を使い、省略せず折り返す。ソルトなしの危険も本文で説明する。アプリ内でのハッシュ計算やユーザーの入力は扱わない。

画像読み取りは、編集画面を開いている間、プレビュー・候補・手修正をメモリで保持する。背景では選択された設定に従って画面を覆い、処理中なら復帰時に再開。閉じる・中止・適用で破棄する。一次OCRと記号領域の再OCR・画像モデルを併用し、全角ASCII相当のみ半角化する。OCRだけでは波括弧などが誤認され得るため、元画素との照合と明示適用を残す。

文字種の表では「記号」セルを切り出し、ラベル・英字・数字の列と分けて照合できる。許可文がなくても記号の並びを候補にする。その場合は「利用先で使える記号か確認してください」と表示し、サービスの許可を自動判定したように見せない。禁止例や入力方法の表を除外し、独立した候補が複数ある場合は絞った画像を案内する。

iOSの「画面の保護」には「アプリ切替時に画面を隠す」を設ける。オフにすると文言・アイコン・背景を含む覆い全体を表示しない。主画面・結果・記号編集・安全性画面で同じ設定を使う。初期値オンで前回の選択を保持し、収録中の結果保護とは独立して扱う。

DBの保存・照合・ソルト比較には、Kotlinの共通教材データを使う。97文字の保存形式は幅と文字サイズに合わせて全文を折り返す。照合の2つの値は小画面・拡大文字で上下、広い画面では左右に配置する。架空の例であることと実際には使用しない旨を短く明記する。


安全性ガイドの導入は連番・予測しやすい変形を実際の文字列で示す。詳細は「避けたい例 / 長さ / パスフレーズ」で切り替え、全例を最初から縦に並べない。iOSはListのリンクから専用画面へ遷移し、アクセシビリティ文字サイズではテーマをメニューにする。AndroidはMaterialシートに固定のテーマ選択を置き、各ボタンの高さを揃え、Foldの縦ヒンジの右側を利用する。

名前・日付・単語・連番・キーボード順・反復、既知の単語の変形には短い理由を添える。長さは0〜9を独立に選ぶ4 / 6 / 8桁の条件を明記し、候補数を切り替える。パスフレーズは実際のEFF収録語7語と、半角スペース / - / _を試せる。24文字の形見本も同じKotlin教材データで共有する。公開例を実用の値としてコピー・生成・保存する操作は設けない。

管理アプリは架空の保存項目と利用の流れ、認証アプリは公開の6桁コード、パスキーは端末での本人確認を含む操作例で伝える。復旧準備は認証の段階数と混同しない位置に置く。偽サイトの説明には予約ドメインによるURLの対比を置き、教材URLはリンクにしない。設定の実値・既存のDB保存図と要素/段階の図は活かし、OS制約や保証範囲の説明は文章で残す。


許可文の右側から次の行へ折り返した記号は、OCR観測配列の順番で切り捨てず、同じ行の対応と後続行の位置関係でまとめる。日本語への少数のOCR誤認がある場合も、許可文に結び付いた記号主体の画素は再読取へ渡す。部分文字列の座標が重なるVisionの結果では、同じ観測から分けた許可文と記号の関係を保持する。プレビューと画像モデルの対象に上段・下段を含め、確認後の明示適用を維持する。


記号一覧の貼り付け欄は枠付きの単一行入力にする。iOSはフォーカス中に枠を強調し、完了キーまたはEnterでキーボードを閉じる。AndroidはOutlinedTextFieldとIME Doneを使用し、シート内のフォーカス・キーボードを操作する。完了では入力を保持し、選択への反映は「記号に反映」で行う。


### 記号案内の表記（タスク25）

前置き・後置きの許可文、引用された項目、単独記号のカンマ列挙、名前と印字の組合せ、短い「記号: -_」見出し、文字種表の別名に対応する。短い見出しはサービスの許可を断定せず、確認候補として表示する。曖昧な引用、禁止・範囲・入力例などでは推測せず理由を表示し、手動で選べる。OCRと画像モデルの候補は行ごとに扱い、画像の照合と明示適用を維持する。検証対象と限界は [記号読み取りのパターン](symbol-import-patterns.md) に記載。

画像読取は既存の画像AI＋OCRを維持し、OCRで案内が見つからない場合はAIによる案内判別で補う。詳細欄は「読み取りの詳細」とし、AIの候補も完全な転記とは断定しない。画像との照合・全記号の手修正・明示適用を維持する。

最小detentでの背景操作にはAppleの [presentationBackgroundInteraction](https://developer.apple.com/documentation/swiftui/view/presentationbackgroundinteraction(_:)) を使用する。標準のシート・ドラッグ・Liquid Glassを保ち、独自の全面ジェスチャーで設定画面を覆わない。

生成ボタンは最後に生成した条件と現在の条件を比較し、結果があり条件が一致するときだけ「再生成」にする。文字種・個別文字・数量・ルール・単語数・区切りの変更では「生成」へ戻し、表示やコピーの安全性設定では変えない。iOS主画面左上の結果ボタンは撤去。iPad・横画面では保持した結果を再生成せずに開く入口を小型の下部操作面へ置く。

## 名前付きプリセット

左上から管理リストを開く。現在の生成条件に名前を付けて端末内へ保存し、一覧の名前から呼び出す。読み込みは生成を開始せず、生成済みの結果・コピー印・表示・安全性設定を維持する。名前と、形式・文字数または単語数・件数・区切りの要約を表示し、現在と一致する設定を示す。
プリセットシートに完了ボタンは置かず、iOSのドラッグハンドル・スワイプ・アクセシビリティのEscape、Androidの戻る・シート操作で閉じる。「現在の設定を保存」の右側に保存ボタンを置き、パスワード形式ではその下にメイン画面と同じ全文字の選択状況を表示する。無効な文字種・個別選択・似た文字の除外も同じ表示部品で反映する。Androidは保存見出しをスクロール領域の外に固定し、キーボード表示時も保存操作を保つ。パスフレーズ形式では文字種設定を使わないため、既存の設定要約を表示する。

iOSは標準Listと一覧内の名前編集、AndroidはMaterialの入力欄・カード一覧・編集ダイアログを使用する。キーボードと拡大文字でも管理画面全体をスクロールできる。既存設定の上書きと削除は明示確認し、同名保存で自動上書きしない。保存中の名前は1〜40 UTF-16単位、保存数は50件、版付きデータは128KiB以内に制限する。破損・未知バージョンは案内を出して書込みを止め、元のデータを保持する。
