## タスク26: 括弧内の記号と折り返した許可語
- 添付の公開ルール部分だけを切り出し、個人情報のないフォームへ配置して失敗を再現。許可語が「使 / 用可能です」に分かれ、各OCR行では許可文として認識されていなかった。
- 位置の近い同じ列の注釈・述語を結び、元の物理行とUTF-16範囲で切り出す。入力項目・伏せ字・否定・無関係な文を挟むと結合しない。
- 括弧を記号そのものとして使うため、対応関係の数え上げで一覧を切らず、閉じる外枠の後ろの許可述語から範囲を判断する。許可注釈に限ってOCRの誤認を含む画素を保持するが、未知文字から記号を作らない。
- OCR用の書式制約と画像モデル用の制約を分け、見落とした実際の括弧を補正可能にした。密な長い行は重なりのある画素領域でも読み、モデルが全体を見失う場合はOCRを残す。
- 記号を直接文字列や文字列配列で返す構造化応答では、字形の揺れや応答解析の失敗が出たため、長い列のモデルに32記号のenumを選ばせ、アプリで半角ASCIIへ変換する。短い一覧は従来の文字列出力とASCII検証を維持する。語彙が画像の許可一覧そのものだとは扱わない。
- 既存画像では縦棒等をバックスラッシュとして追加する回帰も確認。OCRで観測されていないバックスラッシュは画像で追加確認し、確認できなければ解除する。画像モデルによる完全認識は保証せず、プレビュー・手修正・明示適用を維持する。
- モデル単独の読み落としで@等が消える回帰も確認。一次OCRと再OCR、または複数の再OCRで一致した文字は、書式制約の範囲内で維持する。単独のOCR誤認を無条件で足し戻す方式にはしない。
- 一部の記号だけを持つ長い一覧のモデルテストを追加し、出力語彙32種類に埋めないことも検証する。長い列でOCRにないモデル追加候補は、複数の画像読取の一致または接続字形の輪郭との一致を求める。小さな点を消さない高コントラスト化と最近傍拡大、混同する接続字形3種類のOSフォント輪郭照合も併用する。テンプレートや出力語彙から欠落記号を補完せず、モデルが提案した字形の照合に限定する。輪郭処理は画像面積・前景画素・構成部数を制限する。
