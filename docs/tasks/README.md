## タスク23: 折り返した許可記号の読取

- 添付の上段OCRにかなが混ざり、厳密な記号文字列判定で上段を除外していた。許可文の同じ行と後続行を位置で選び、記号主体の画素に少数の誤認文字が混ざっても再読取へ渡すよう修正。
- 許可文と記号を同じ観測から分けた関係を保持し、部分文字列の矩形が重なっても上段を失わない。観測配列の順番に依存せず、行ごとに切り出してプレビュー・OCR・画像モデルへ渡す。
- 数字や従来許容していたOCR誤認文字を未知文字の上限へ重複計上しない。未知文字から記号を推測して追加する処理は設けず、従来の幅違い正規化と対応ASCII記号への限定を維持。
- 画像モデルへ、許可文の横の最初の記号行と折り返し行のすべてを読み取ることを明記。許可文の文章そのものは記号として返さない。
- 禁止・除外・入力例・URL・メールアドレス・装飾線・間の文章・遠いブロックを除外する回帰テストを追加。複数の独立した許可文をまとめない既存ガードも維持。
- 添付の公開規則部分だけを画像テストに収録。上段の# / %と下段の@ / ~、両行のプレビュー、元画像にないバックスラッシュを追加しないことを検証。

| 検証 | 結果 |
|---|---|
| iOS 18 SE Simulator | ユニット51件成功・画像モデル要件の2件スキップ、UI3件成功 |
| iOS 27 Simulator | 全ユニット53件成功。添付画像の画像モデル推論を実際に使用するテストも成功。UI3件成功（個別再実行を含む） |
| 最終の境界・画像回帰 | iOS 27で7件成功。iOS 18で適用UIも含む7件成功・画像モデル1件スキップ |
| 画像の目視確認 | 両OSで添付の記号の上段・下段がプレビューに残ることを確認 |

UI用の合成画像はOCRのみで処理する。フォントによって@が候補から落ちるケースは手修正して適用する操作も検証した。添付の元画像では@を含む上下の候補とモデル推論を別テストで確認。全画像・全文字の完全認識を保証せず、画像との照合・手修正・明示適用を維持する。実機は使用していない。


## タスク24: 記号貼り付け欄の枠と完了キー

- iOSの貼り付け欄を、フォーカス時に強調する枠付きの単一行TextFieldに変更。改行キーをDone / 完了へ変更し、submitでキーボードを閉じる。
- AndroidはOutlinedTextFieldの枠を使い、単一行・IME Doneへ変更。モーダル内で取得したフォーカスとキーボードのコントローラーを使って終了する。
- 完了では入力を保持し、選択内容は変更しない。「記号に反映」で適用し、その際にもキーボードを閉じる。
- iOS 27 Simulatorでソフトキーボードの完了、iOS 18 SE SimulatorでReturnによる終了と従来の背景コピー・貼り付けを確認。入力保持・改行なし・明示適用をUIテストで検証。
- AndroidのDebug / AndroidTest APK・Lint成功。閉じたFoldで2件（Done・未対応文字の貼り付け）、開いたFoldでDoneの1件成功。IME非表示・フォーカス解除・入力保持・適用を確認し、開閉状態を元へ復元。
- 両OSの枠とキーボード終了後の表示を保存画像で目視確認。生成・OCRの処理は今回の検証対象に含めていない。


## タスク25: サービスの記号案内の表記パターン

- 実装前に [パターン表](../design/symbol-import-patterns.md) を作成してコミット。許可文の前置き・後置き、助詞、引用列挙、カンマ列挙、名前と印字、短い見出し、文字種表の別名、折り返しを整理した。
- Kotlin共通層に表記解析を追加。文言と値の書式を分け、8種類×7書式の56組合せを検証。全角ASCII相当の値・引用符・区切りを扱い、元のUTF-16範囲からVisionの画素へ対応付ける。
- 引用や列挙の区切り、見出しの（半角）/ (ASCII)、名前を囲む括弧を候補へ混ぜない。値そのものが引用符・カンマの場合は保持。記号名だけでは推測せず、字形との一致が必要。
- 行ごとの書式制約でOCRの誤読を正解集合に固定せず、画像モデルが実際の字形を補正できるようにした。有効なモデル候補でその行のOCRを置換し、読めない行はOCRを残す。
- 禁止だけの一覧、例外、明示された正規表現・コード範囲、入力例・URL・対応外字形は許可記号へ推測変換しない。引用と直接列挙の混在、伏せ字、列挙の直後の除外条件も、一部だけを許可一覧にしない。独立した複数の規則を合成しない既存ガードを維持。
- 短い「記号: -_」も確認候補として扱い、サービスが許可したと断定しない。未確定の理由を表示し、画像との照合・手修正・明示適用を維持する。

iOS 18のVisionでは書体により@や引用符が誤読される。合成画像の一部は候補の欠落や構文未確定になり、構文が未確定なら候補を自動で作らず手動選択へ進む。OS間で同じOCR出力を保証するテストにはせず、書式を余計な記号として取り込まないことも検証する。iOS 27の画像モデルでも完全認識は保証しない。実機・外部サービスは使用せず、画像は公開の規則部分と合成例のみ。作業前からのXcode project / Info.plistの差分は含めない。
