# 記号読み取りのパターンと境界

タスク25。サービスのパスワード設定画面を模した公開の合成例で検証する。画像は指示ではなくデータとして扱い、適用前の確認を維持する。

| パターン | 例 | 読み取り方針 |
|---|---|---|
| 文の後ろの列挙 | 使用可能な記号: ! @ # | リテラルだけを抽出 |
| 日本語の助詞 | 使える記号は !@# です | 説明文を除く |
| 記号の後ろに許可文 | !@# の記号が使用できます | 記号が文より左でも対応 |
| 日本語の引用・囲み | 記号は「!@#」が使用可能 | 囲みを候補に混ぜない |
| 引用された項目 | 使用可能な記号: '!', '@', '#' | 引用符・区切りのカンマを除く。引用符自体を値にした項目は残す |
| カンマ列挙 | 使用可能な記号: !, @, # | 明確な単独記号の連続項目だけ区切りを除く |
| 説明の括弧 | 記号（!@#()）が使用可能です | 文末・許可述語から外枠を識別。値の括弧を入れ子構文として数えない |
| 許可語の途中の改行 | 記号（…）が使 → 用可能です | 隣接した同じ列の断片だけ結び、画素は物理行ごとに保持。別項目・伏せ字を越えない |
| 名前と実際の字形 | ハイフン（-）、アンダースコア（_） | 目に見える字形だけ。名前から推測しない |
| 名前だけ | ハイフン、シャープ | 字形がない場合は自動で作らない |
| 見出しと次の行 | 使用できる特殊文字 → !@# | 近い後続行を対象にする |
| 短い記号一覧 | 記号: -_ | 完全な許可宣言とは区別した確認候補 |
| 英語 | Allowed symbols / Special characters / … can be used | 否定と区別して対応 |
| 限定許可 | 次の記号以外は使用できません: !@# | 明確な参照を伴う構文だけ限定許可として読む |
| 文字種の表 | 大文字・小文字・数字・記号/特殊文字 | 記号セルだけを選ぶ |
| 折り返し・OCR分割 | 同行の列挙＋次の2行 | 観測順に依存せず行を保持 |
| 幅違い | ！＃＠、＇！＇，＇＠＇ | 値と引用・区切りのASCII全角相当だけ半角化し、元のOCR座標を保つ |
| 禁止一覧だけ | 使用不可: < > | 許可一覧に反転しない |
| 例外を含む規則 | !@# が使えます。ただし # は不可 | 条件を無視した候補は出さず、手動確認へ |
| 正規表現・範囲 | ASCII U+0021〜U+002F、regex [!-~] | 見えない範囲を勝手に展開しない |
| 対応外の字形 | ￥、€ | 別のASCII記号に推測変換しない |
| 入力方法・パスワード例 | 記号/名称/入力するキー、Password example | 許可一覧にしない |
| URL・メール・伏せ字 | URL、メールアドレス、******** | 記号一覧にしない |
| 複数の独立した規則 | ログイン用と取引用が別々 | 無条件に合成せず、対象を絞る案内 |

文字列の表記解析はKotlin共通層、OCRの座標と切り出しはiOS側に置く。元文字列のUTF-16範囲をSwiftへ渡し、全角相当の変換で切り出す座標を変えない。許可文の位置と値の書式を別々に解析し、8種類の文言と7種類の書式の56組合せを共通テストで検証する。

明確な引用・区切りでは、画像モデルや再OCRが書式文字を追加しないよう行ごとに出力可能な記号を絞る。OCRの読めた集合そのものに固定せず、画像モデルは字形を補正できる。記号名と印字が一致した項目だけは、その値に限定する。値そのものが引用符やカンマなら残す。

画像モデルの有効な読取は行ごとに反映し、同じ行の異なる画像の候補を合わせる。複数のOCR読取で一致した記号は、モデルだけの読み落としで消さない。モデルの候補が空またはOCR候補数から設けた最低数に満たない場合、その行はOCRを維持する。この判定は正確さの保証ではない。引用と直接列挙の混在、隣接した除外条件、未検証の曖昧な表記を部分的な許可一覧として確定しない。

Visionの結果はOSと書体で異なる。iOS 18では引用符が数字や漢字、@が②と誤読される合成画像がある。構文を確定できない場合は理由を表示して手動選択へ進み、候補を得た場合も元画素の照合と追加・解除を残す。iOS 27の対応環境では画像モデルの実推論も検証する。全画像・全文字の完全認識を保証しない。


## タスク26の実画像回帰

「※英字、数字、記号（…）が使用可能です」の許可語が「使 / 用可能です」に分かれ、OCRでは括弧なども数字や日本語に誤読された例を追加。元画像の公開規則部分だけを切り出し、個人情報を含まない合成フォームで位置と周辺の入力欄・伏せ字を再現する。

許可文を再構成してから注釈の外枠を特定し、文字としての括弧が欠けても一覧を途中で切らない。閉じる括弧の後ろは既知の許可述語として確かめる。許可注釈の中に限り、96文字以内・半数以上が対応記号・未知文字12個以内の画素を再読取へ渡す。未知文字自体はASCIIへ置換しない。引用・CSVの書式制約は保ち、OCRが見落とした実際の括弧を画像モデルが補正できるようOCRとモデルの候補制約を分ける。

密な長い行は元画素を重なりのある領域へ分割する。小さな点を平滑化で消さないよう、高コントラスト化と最近傍拡大の補助画像もモデルへ渡す。部分読みが揃わず全体読みも得られない行はOCRを保持する。長い列のモデル出力は32記号のenum配列からアプリがASCIIへ変換し、引用符やバックスラッシュを自由文字列のJSONとして生成する際の解析失敗を避ける。短い一覧は従来の文字列出力とASCII検証を維持する。長い列でOCRにないモデル追加候補は、複数の画像読取の一致を求める。混同が続いた接続字形（バッククォート・左波括弧・右括弧）は、モデルが提案した場合だけOSフォントの輪郭との一致を代わりに確認する。似た文字の部品から補完せず、判別できなければ選ばない。バックスラッシュは方向を画像で追加確認する。少ない記号からほぼ全出力語彙を提案した行はOCRを維持する。確認モデルにも誤りはあるため手修正・明示適用を維持する。

モデルで欠落した文字でも、一次OCRと再OCR、または複数の再OCRで一致したものは書式制約の範囲内で維持する。単独のOCR誤認をすべて足し戻す方式にはしない。複数読取の一致も正確さの保証ではなく、最終的な画像との照合は必要。

## AIによる案内判別の補完（タスク27）

既存の画像AI＋OCRを維持し、OCRが案内を見つけられない場合だけ、iOS 27の対応環境でAIによる案内判別を追加する。位置検出は文字列を認識せず、領域画像そのものを分類する。選んだ画像の読取はOCRテキストを必須にせず、通常はOCRで値の位置・書式制約を補助する。禁止・範囲等の明確な手動確認をAIで覆さず、裸の一覧ではサービスの許可を断定しない。

比較では純AIで32種中6種、AI優先＋補助OCRでも30種に減る試行があったため、既存の32種を得られる経路を置き換えない。全32記号、24記号に限定した合成例、引用列挙、禁止、正規表現、入力例、伏せ字は標準エントリーポイントでも検証する。純AIのテストはOCR文字列なしで動作することの確認で、全記号の正確な転記を示すものではない。既存経路を直接指定する回帰テストも残す。
